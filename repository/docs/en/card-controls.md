# Suspension, deletion and shared fields

## Pause one study card

An Anki note can generate several study cards, such as a forward and a reverse card. Open **Card suspension, deletion and shared fields** in Rudonium settings. The default marker is `SUSPEND`. To rename it, enter your own text and choose **Save marker**. Existing notes can still use its old name.

```markdown
- Bahnhof :: railway station
SUSPEND_2
<!--ID: 1700000000101-->
```

| Line immediately above the note ID | Cards to suspend |
| --- | --- |
| `SUSPEND` | Every study card generated by this note |
| `SUSPEND_2` | The second template's card |
| `SUSPEND_1,3` | The first and third templates' cards |

Numbers start at one. For cloze notes, the number is the cloze index. If the text has only `c1` and `c3`, use `SUSPEND_3` for the third deletion. Existing space-separated markers such as `SUSPEND 2` are also recognized. See [whole-page commands](#commands-on-a-whole-page-card) for page cards.

**One-way export** enforces the marker each time its source is in scope, including an unchanged file. If you resume a card in Anki while its marker remains, the next export suspends it again. To resume it permanently, remove the marker and resume the card in Anki.

**Bidirectional sync** previews the change. The first sync combines existing Anki suspensions with the cards marked in Markdown. Later syncs track changes for each study card independently. Resuming one sibling in Anki removes its number from Markdown when you apply the preview. Removing a previously synchronized marker in Markdown lets you review and apply the corresponding resume action in Anki. After a connection error, open a new preview to read the actual state. If Anki regenerated a study card or the templates changed while you edited the marker, compare the old and new IDs in the preview. Choosing the Anki state establishes the new mapping without changing the schedule.

### Commands on a whole-page card

Use the same place for `SUSPEND`, numbered forms and your configured `DELETE` command on every linked page. Write one command on its own line directly under the first H1. If the page tag is on its own line there, the command may follow the tag. With a heading ID the command goes above that ID. With a YAML or footer ID the command stays under the H1.

This example suspends the second study card of a page linked through YAML.

```markdown
---
anki-page-ID: '1700000000101'
---
# How do you say “station” in German? #anki-page
SUSPEND_2

Bahnhof.
```

To delete the linked Anki note, replace the command line with `DELETE` and run sync. For a new page, export it and let Rudonium save its ID before issuing either command. Rudonium reports a command on an unlinked page so you can remove it, link the page and then put it back.

## Delete an Anki note

With a local-notes boundary, the **Remove block** deletion policy keeps the Markdown page and its previous ID when the Anki note is deleted. This protects the private notes on later exports. The deletion preview shows this exception.

On a block card, write your configured deletion marker immediately above its note ID. On a card page, write it under the H1. `DELETE` removes the entire Anki note, all its study cards and their review history. Use suspension for a temporary break.

Choose a deletion marker distinct from the card start and end lines. If the marker is repeated above one ID, remove the extra copy and run the sync again. In a regular multicard note, a `DELETE` line inside a `FROZEN` declaration stays within that declaration.

```markdown
- Bahnhof :: railway station
DELETE
<!--ID: 1700000000101-->
```

After Anki confirms deletion, Rudonium clears the command. By default it retains the recognized source block and its ID, so you can keep your material without exporting it as a new note. A standalone command and ID with no associated block are both removed. If a custom regex makes the source boundaries uncertain, Rudonium preserves the ID and the source text.

Choose one option under **Markdown after confirmed Anki deletion**.

| Option | What appears in Obsidian |
| --- | --- |
| **Keep text and ID** | The default. Keep the original block and its ID. |
| **Remove card block** | Remove the recognized block. Moving an entire `@page` file to the vault trash also requires enabling the page trash switch. |
| **Keep and mark as deleted** | Keep the text readable and add **Deleted from Anki** below it. |
| **Strike through the whole card** | Display the entire question and answer with a strikethrough. The Markdown file uses a native HTML `<del>` element. Rich Markdown appears as struck-through text. |
| **Hide in an HTML comment** | Reading view shows no card text or status. The Markdown source retains the card and ID in a comment. A page keeps its filename and YAML properties. |

The three archive options reserve the ID and exclude the card from future exports. The struck-through and hidden formats preserve the exact source, including line endings. Nested ID comments are escaped so that they cannot close the enclosing comment. The strikethrough and hidden representations also work in Reading view with the plugin disabled. Ordinary `~~strikethrough~~` in a live note has no effect on sync.

Upgrades retain the previous selection. Cards archived by 0.8.5 keep their original presentation. The selected option applies to subsequent confirmed deletions.

### How Rudonium knows the note existed

1. A successful bidirectional sync receives the actual Anki note for the given note ID. The local history for the active profile records this observation together with a fingerprint of the source block and its path. This also happens in **Keep text and ID** mode.
2. If a note disappears, Rudonium checks that the stored observation matches the active profile and unchanged Markdown block and that the ID has a unique source. Before changing Markdown, it looks up the ID again across the whole collection. Open a bidirectional preview of the note or selected scope to process an externally removed note. Moving a note to another deck or removing just one of its reverse-template cards does not remove the Anki note.
3. The bidirectional preview shows the proposed action. An ID with no prior observation, a connection error, a profile switch or changed source cannot authorize automatic cleanup. Older links without this evidence need one successful sync while the Anki note still exists. This comparison detects disappearance from the collection. It cannot distinguish manual deletion from restoring an older Anki collection.

A previous one-way export by itself does not establish ownership of this exact Markdown block and path. If the note is already missing on the first bidirectional sync, the source is retained. Opening a preview alone does not commit a new observation.

For **one-way export**, your explicit `DELETE` command (or configured marker) requests the deletion. After Anki confirms the result, Rudonium clears the command and applies the selected option. Without confirmation, the command stays in the note for retry.

## Add a shared source with FROZEN

If ten cards in one note came from the same book chapter, run **Edit shared fields in this note** or choose **Edit shared fields** in settings. Select an Anki note type, fill in `Source`, then choose **+ Add field** and select `Chapter`. Each list offers available fields from your model. Refresh the Anki note types if a field is missing.

```markdown
FROZEN - Geography:
Source: Atlas of Austria
Chapter: Lower Austria
```

The editor displays every field already in the block. Review the complete preview and choose **Save in note**. **Remove field** removes a row from the draft. Removing the last field requires choosing **Remove block**. **Cancel** closes without saving. A single editor undo reverses the entire saved change.

On regular export, the value is appended to that field in notes of the selected type in this file. Each note type can have one block containing several fields. For a whole-page card use the placement shown below. [Obsidian_to_Anki syntax](https://github.com/ObsidianToAnki/Obsidian_to_Anki/wiki/Frozen-Fields)

For `START/END` blocks and standard regex cards, choose a field in your Anki model. Rudonium’s linked-bullet format appends shared values only to `Front` and `Back`. Use regular export for composed values. When shared text makes a field differ from its editable Markdown source, bidirectional sync skips editing that field.

#### Shared fields on a page

Run **Edit shared fields in this note** on a marked page. The editor places the declaration before the answer, after the heading, any command and any ID stored under the heading. Keep one blank line after the last shared field. This example uses an Anki type named `Geography` with an additional field named `Source`.

```markdown
# What is the capital of Austria? #anki-page
FROZEN - Geography:
Source: Atlas of Austria

Vienna.
```

Use your configured marker in place of `FROZEN`. The shared value goes from Markdown to the Anki field. Anki edits do not replace this declaration. The question, answer, file link and context keep their existing sources. Define an extra field in one place on this page. If the same field appears both here and under `<!--anki-fields-->`, remove one definition and sync again.

### Moving cards and keeping sync history

Move the existing ID along with the question and keep a single copy within the selected folders. When file links or heading context are enabled, syncing refreshes the configured fields on the same Anki note. If a generated part of a field was edited in Anki and its origin cannot be verified, review the issue in the preview.

Rudonium 0.8.7 reads 0.8.6 checkpoints. In larger profiles it saves small ID changes in a journal alongside the snapshots. Back up all of a profile’s `bidirectional-sync.json.*` files together. To roll back to 0.8.6, restore its corresponding state backup, since that version cannot read the new format.

## File destination deck

A directive such as `TARGET DECK: Knowledge::Vienna` selects the destination for the whole file. Keep one destination per file. If two active directives disagree, Rudonium reports both line numbers and skips that note. To use separate decks, split the cards into different files or configure export rules and omit the file directive. Examples inside code fences, YAML and comments can stay in the text.

## Date and text after an ID

On a separate marker line, the number after `ID:` links the block to Anki. With dates enabled, a confirmed `ID: 1795000000001 ★ checked` becomes `ID: 1795000000001 | 2026-11-20 ★ checked` (example date). Disabling dates preserves existing dates. Separate any annotation beginning with a digit from the ID with a space. Digits attached directly extend the ID.
