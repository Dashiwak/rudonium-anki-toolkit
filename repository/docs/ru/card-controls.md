# Приостановка, удаление и общие поля

## Приостановить одну учебную карточку

Одна запись Anki может создавать несколько учебных карточек, например прямую и обратную. В настройках Rudonium откройте **Приостановка, удаление и общие поля**. По умолчанию метка называется `SUSPEND`. Чтобы переименовать её, введите, например, `ПАУЗА` и нажмите **Сохранить метку**. Прежнее имя продолжит распознаваться в существующих заметках.

```markdown
- Bahnhof :: вокзал
ПАУЗА_2
<!--ID: 1700000000101-->
```

| Строка непосредственно над ID | Какие карточки поставить на паузу |
| --- | --- |
| `ПАУЗА` | Все карточки записи |
| `ПАУЗА_2` | Только карточку второго шаблона |
| `ПАУЗА_1,3` | Карточки первого и третьего шаблонов |

Номер начинается с единицы. Для Cloze номер соответствует пропуску: если в тексте есть только `c1` и `c3`, для третьего пропуска используйте `ПАУЗА_3`. Прежняя запись через пробел, например `SUSPEND 2`, также читается. Для страниц см. [пример команды под заголовком](#команды-на-странице-карточке).

**При односторонней синхронизации** метка действует при каждом экспорте выбранной области. Если вы возобновили карточку в Anki и оставили метку в Obsidian, следующий экспорт снова поставит её на паузу. Чтобы возобновить повторения надолго, уберите метку в Markdown и возобновите карточку в Anki.

**При двусторонней синхронизации** откройте предпросмотр. При первой сверке Rudonium объединяет уже существующие паузы с указанными в Markdown. В дальнейшем программа учитывает изменения отдельно по каждой учебной карточке. Если вы возобновили одну карточку в Anki, её номер исчезнет из метки после применения. Если вы удалили ранее сверенную метку в Markdown, предпросмотр предложит возобновить соответствующие карточки в Anki. При ошибке связи повторно откройте предпросмотр для проверки фактического состояния. Если Anki пересоздала учебную карточку или при изменении шаблонов вы одновременно изменили метку, сверьте прежние и новые ID в предпросмотре. Выбор состояния из Anki запоминает новое соответствие без изменения расписания.

### Команды на странице-карточке

На всех связанных страницах место для `SUSPEND`, команды с номерами и настроенной команды удаления `DELETE` одинаковое. Запишите одну команду отдельной строкой сразу под первым заголовком H1. Если там отдельно стоит тег страницы, команду можно поставить за ним. При ID под заголовком команда окажется над ID. При ID в YAML или после ответа оставьте команду под H1.

В примере ID хранится в YAML, а команда приостанавливает вторую учебную карточку этой записи.

```markdown
---
anki-page-ID: '1700000000101'
---
# Как по-немецки «вокзал»? #anki-page
SUSPEND_2

Bahnhof.
```

Чтобы удалить связанную запись Anki, замените команду на `DELETE` и запустите синхронизацию. Новую страницу сначала экспортируйте, чтобы Rudonium записал её ID. Если команда стоит на странице без ID, плагин выдаст замечание. Уберите команду, привяжите страницу и затем верните команду.

## Удалить запись через DELETE

Если в странице есть граница личных заметок, в режиме **Удалить блок** после удаления записи из Anki сохраняются Markdown-страница и её прежний ID. Так личные записи остаются защищёнными и при следующем экспорте. Эта особенность указана в предпросмотре удаления.

У карточки-блока напишите настроенную метку удаления непосредственно над ID. У страницы-карточки поставьте её под H1. `DELETE` удаляет запись Anki целиком вместе со всеми учебными карточками и их историей. Для временного перерыва используйте приостановку.

Выберите метку удаления, которая отличается от строк начала и конца карточки. Если над одним ID стоит две метки удаления подряд, уберите лишнюю и повторите синхронизацию. В обычной заметке с несколькими карточками строка `DELETE` внутри объявления общих полей `FROZEN` остаётся частью этого объявления.

```markdown
- Bahnhof :: вокзал
DELETE
<!--ID: 1700000000101-->
```

По умолчанию после подтверждения удаления в Anki Rudonium убирает команду и сохраняет распознанный блок с его прежним ID. Это позволяет оставить исходный материал и предотвращает случайное создание той же записи заново. Для самостоятельной команды без связанного блока убираются обе служебные строки. Если своё регулярное выражение не позволяет надёжно определить границы карточки, Rudonium сохраняет ID и исходный текст.

В настройке **Что делать с текстом после удаления записи в Anki** выберите один вариант.

| Вариант | Что вы увидите в Obsidian |
| --- | --- |
| **Оставлять текст и ID** | По умолчанию сохраняются исходный блок и прежний ID. |
| **Удалять блок карточки** | Убирается распознанный блок. Для переноса целой страницы `@page` в корзину включите отдельный переключатель. |
| **Сохранять с пометкой «Удалено из Anki»** | Текст читается как прежде. Под ним появляется подпись **Удалено из Anki**. |
| **Зачёркивать всю карточку** | Всё содержимое вопроса и ответа отображается зачёркнутым. Для переноса между программами используется встроенный в Markdown HTML-элемент `<del>`. Сложная разметка показывается зачёркнутым текстом. |
| **Скрывать в HTML-комментарии** | В режиме чтения на месте карточки ничего не отображается. Исходный текст и ID хранятся в комментарии файла Markdown. У страницы сохраняются имя файла и свойства YAML. |

Три варианта архивирования сохраняют ID и исключают карточку из последующих экспортов. Для зачёркнутого и скрытого вариантов Rudonium хранит точную копию исходного блока, в том числе исходные переводы строк. Вложенные комментарии с ID экранируются, чтобы не закрыть внешний комментарий раньше времени. В режиме чтения зачёркивание и скрытие работают и при отключённом плагине. Зачёркивание, которое вы сами поставили в обычном тексте через `~~слово~~`, не управляет синхронизацией.

При обновлении сохраняется прежний выбор. Оформление уже архивированных в 0.8.5 карточек сохраняется. Новая настройка действует при следующих подтверждённых удалениях.

### Откуда Rudonium знает, что запись раньше существовала

1. При успешной двусторонней сверке Rudonium получает из Anki саму запись по её ID. В локальной истории соответствий для активного профиля сохраняется подтверждение вместе с отпечатком исходного Markdown-блока и его путём. Это происходит и в режиме **Оставлять текст и ID**.
2. Если при следующей сверке запись пропала, Rudonium проверяет, что история относится к тому же профилю и неизменившемуся блоку, а ID в хранилище однозначен. Перед изменением Markdown плагин повторяет поиск ID по всей коллекции Anki. Для обработки отсутствующей записи откройте двусторонний предпросмотр заметки или выбранной области. Перемещение в другую колоду и удаление лишь одной учебной карточки обратного шаблона сами по себе не удаляют запись.
3. Действие для источника показывается в двустороннем предпросмотре. Новая запись или ID, которого Rudonium прежде не подтверждала, ошибка соединения, смена профиля и изменённый исходник не дают права очищать текст. Для старых связей без подтверждения нужна успешная сверка, пока запись ещё существует. Проверка устанавливает исчезновение из коллекции. Причину исчезновения, например ручное удаление или восстановление старой копии Anki, она определить не может.

Если до этого работал только односторонний экспорт, его журнал полей сам по себе не подтверждает принадлежность записи конкретному блоку и пути Markdown. Если запись уже исчезла к первой двусторонней сверке, исходный текст сохраняется. Открытие предпросмотра само по себе не записывает новую контрольную точку.

При **одностороннем экспорте** основанием служит ваша явная команда `DELETE` (или заданное в настройках слово). Плагин убирает команду и применяет выбранное действие к Markdown после подтверждения из Anki. Если подтверждения нет, команда сохраняется для повторной проверки.

## Добавить общий источник через FROZEN

Если десять карточек в одной заметке взяты из одной главы книги, выберите команду **Общие поля этой заметки** или кнопку **Редактировать общие поля** в настройках. Выберите тип записи Anki, заполните поле `Source`, затем нажмите **+ Добавить поле** и выберите `Chapter`. В списке предлагаются свободные поля вашей модели. Если нужного поля ещё нет, обновите список типов записей из Anki.

```markdown
FROZEN - Geography:
Source: Атлас Австрии
Chapter: Нижняя Австрия
```

В окне сразу видны все поля текущего блока. Проверьте общий предпросмотр и нажмите **Сохранить в заметке**. Кнопка **Убрать поле** исключает одну строку из предпросмотра. При удалении последнего поля подтвердите **Удалить блок**. **Отмена** закрывает окно без записи. Все сохранённые изменения можно отменить одной командой редактора.

При обычном экспорте общее значение добавляется к одноимённому полю записей этого типа в текущем файле. На один тип записи в файле приходится один блок; в нём может быть несколько полей. На странице-карточке используйте положение блока, показанное ниже. [Синтаксис Obsidian_to_Anki](https://github.com/ObsidianToAnki/Obsidian_to_Anki/wiki/Frozen-Fields)

В блоках `START/END` и штатных карточках по регулярным выражениям можно выбрать поле своей модели. Для связанных карточек-списков Rudonium добавляет общий текст только к `Front` и `Back`. Используйте обычный экспорт для составных значений. Когда общий текст делает поле в Anki отличным от исходного поля в Markdown, двусторонняя синхронизация пропускает правку такого поля.

#### Общие поля на странице

На отмеченной странице выполните команду **Общие поля этой заметки**. Редактор поставит объявление перед ответом, после заголовка, команды и ID, если они стоят под заголовком. После последнего общего поля оставьте пустую строку. В примере у типа записи `Geography` есть дополнительное поле `Источник`.

```markdown
# Как называется столица Австрии? #anki-page
FROZEN - Geography:
Источник: Атлас Австрии

Вена.
```

Вместо `FROZEN` можно использовать своё обозначение из настроек. Значение передаётся из Markdown в поле Anki. Изменение в Anki не переписывает строку FROZEN в Obsidian. Вопрос, ответ, ссылка на файл и контекст заполняются своим обычным способом. Для дополнительного поля достаточно одного определения. Если оно указано и здесь, и в разделе `<!--anki-fields-->`, уберите одно из определений и повторите синхронизацию.

### Перенос и история синхронизации

Если вопрос перенесён в другой выбранный файл или под другой заголовок, оставьте прежний ID в одном месте и запустите синхронизацию. При включённых настройках ссылки и контекста плагин обновит соответствующие поля существующей записи. Если в Anki вручную изменена служебная часть поля и прежний источник нельзя подтвердить, проверьте замечание в предпросмотре.

Rudonium 0.8.7 читает снимки 0.8.6. Для больших профилей небольшие изменения записываются по ID в журнал рядом со снимками. Для резервной копии сохраняйте вместе все файлы `bidirectional-sync.json.*` профиля. Версия 0.8.6 не читает новый формат. При возврате к ней потребуется её собственная согласованная копия состояния.

## Целевая колода файла

Директива `TARGET DECK: Knowledge::Vienna` задаёт колоду для всего файла. Укажите одну колоду. Если встречаются два разных действующих значения, плагин сообщает обе строки и останавливает обработку этой заметки. Для разных колод разнесите карточки по файлам либо используйте настроенные правила экспорта без файловой директивы. Примеры директив в блоках кода, YAML и комментариях можно оставить в тексте.

## Дата и приписка после ID

На отдельной строке число после `ID:` связывает блок с записью Anki. Например, при включённой дате строка `ID: 1795000000001 ★ сверено` после подтверждения связи принимает вид `ID: 1795000000001 | 2026-11-20 ★ сверено` (дата для примера). При выключении опции уже записанная дата сохраняется. Если приписка начинается с цифры, отделите её от ID пробелом. Отдельные цифры, добавленные вплотную, меняют само число.
