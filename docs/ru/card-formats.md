# Форматы карточек в Markdown

В разделе **Правила типов записей** выберите формат для нужного типа записи Anki. Первые два захваченных значения заполняют первые два поля в порядке, заданном в Anki. Во всех примерах ниже один и тот же вопрос и ответ. Выберите формат, затем скопируйте соответствующий пример в заметку.

| Формат | Когда его выбрать |
| --- | --- |
| START / END | Нужно явно задать тип записи и подписать поля их именами из Anki |
| RemNote · одна строка | Короткий вопрос и ответ разделяются двумя двоеточиями |
| Neuracache · #flashcard | За помеченным тегом вопросом следует одна строка ответа |
| Вопрос и ответ · Q: / A: | У вопроса и ответа есть видимые подписи |
| Spaced Repetition · разделитель ? | Между строкой вопроса и строкой ответа нужен отдельный разделитель |
| Два столбца таблицы · одна карточка | Одна карточка занимает отдельную таблицу из трёх строк |
| Целая страница · #anki-page | Заголовок посвящённой карточке страницы служит вопросом, текст — ответом |

## Создать правило по разделителю

Выберите тип записи в **Быстром старте** или откройте добавление либо редактирование правила в разделе **Правила типов записей**. Нажмите **Мастер регулярных выражений**, укажите количество полей, введите разделитель и проверьте одну строку Markdown. Например, для словарной записи с четырьмя полями подойдёт двоеточие:

```markdown
Wirtshaus : трактир : ein altes Wirtshaus : de_DE
```

Мастер покажет все четыре значения рядом с настоящими именами полей Anki. Кнопка **Использовать формат** переносит выражение в форму. Чтобы включить правило, нажмите **Сохранить настройки** или **Сохранить правило**. При повторном открытии созданного правила мастер вспомнит число полей и разделитель.

Все части строки должны быть непустыми и идти в порядке полей типа записи. Если в тексте встречаются двоеточия, используйте другой разделитель, например `||`. Если строка подходит под два правила мастера, экспорт укажет строку и оба типа записи. Измените один из разделителей или перепишите строку. При первом экспорте ID появится под строкой. Сохраняйте его при правках, и односторонний экспорт обновит ту же запись Anki. Если в Anki переставили поля, обновите список типов записей, откройте мастер и подтвердите новый порядок.

### Многострочный ответ в мастере

Выберите **Формат ответа → Несколько абзацев**. Для двух полей разместите вопрос на первой строке под `:::anki`. Ответ начинается на следующей строке. Внутри ответа можно оставлять пустые строки, списки и двоеточия. Завершите карточку отдельной строкой `:::`. После экспорта ID располагается под ней.

```markdown
:::anki
Как узнать венский трактир?
На вывеске может быть написано Wirtshaus.

В меню обычно есть блюда местной кухни.
:::
```

Для трёх и более полей соберите первые поля в одну строку, используя разделитель. Например, при четырёх полях первая строка может быть `Wirtshaus : трактир : de_DE`, а ниже пойдут абзацы четвёртого поля. Если в примере обнаружится незакрытый блок, лишний ID внутри карточки, служебная команда или сразу два подходящих типа записи, плагин укажет строку для исправления.

### START / END

Используйте маркеры блока из настроек и точные названия типа записи и полей в своей Anki.

```markdown
START
Basic
Front: Столица Австрии?
Back: Вена
END
```

У связанного блока эти имена определяют, в какие поля Anki попадут изменения. [Как синхронизируются именованные поля](#как-синхронизируются-именованные-поля)

### RemNote

```markdown
Столица Австрии? :: Вена
```

После ответа можно указать язык вопроса и ответа: `- Вопрос?+++ :: Ответ :: F=ru_RU :: B=de_DE`. Языки записываются в поля `FrontLang` и `BackLang`, если такие поля есть в модели Anki. В двухполевой модели сохраняются вопрос и ответ, метки языка остаются в Markdown. Метка `:: R` требует поля `Add Reverse`. Существующий пользовательский шаблон продолжает работать по своим правилам.

### Neuracache

```markdown
Столица Австрии? #flashcard
Вена
```

### Q: / A:

```markdown
Q: Столица Австрии?
A: Вена
```

### Spaced Repetition

```markdown
Столица Австрии?
?
Вена
```

### Таблица из двух столбцов

Для каждой карточки создавайте отдельную таблицу. У неё есть заголовки, строка-разделитель и одна строка данных. ID записывается после таблицы.

```markdown
| Вопрос | Ответ |
| --- | --- |
| Столица Австрии? | Вена |
```

### Целая страница

В разделе **Правила типов записей** назначьте формат целой страницы (`@page`) одному типу Anki с двумя или более полями. Напишите вопрос в первом заголовке первого уровня (`#`), а под ним — непустой ответ. Поставьте тег `#anki-page` в любом месте обычного Markdown или добавьте `anki-page` в свойство YAML `tags`. По этому тегу Rudonium узнает страницу ещё до получения ID. Перед вопросом допустимы свойства YAML, пустые строки, комментарии и отдельная строка тегов. Напишите обычный текст под заголовком. Можно поставить тег и ниже границы личных заметок. Он пометит страницу, а сами личные заметки останутся в Obsidian. Тег внутри примера кода, комментария или ссылки пропускается. Связанная страница сохраняет номер записи Anki при изменении вопроса или имени файла.

Для новых связей по умолчанию выбрано **В свойствах (YAML)**. Если вы раньше сохранили другой выбор, Rudonium его учитывает. В разделе **Маркеры ID Anki → Расположение ID страницы-карточки** задаётся место для будущих связей. Уже связанная страница сохраняет прежний ID на прежнем месте.

| Расположение | Где будет записан ID |
| --- | --- |
| В свойствах (YAML) | В текстовом свойстве `anki-page-ID: '1700000000001'` перед заголовком. |
| Под заголовком | На отдельной строке под вопросом. Настройка комментариев определяет, будет ли ID виден при чтении. |
| После ответа | В скрытой строке вида `<!--ID: 1700000000001 @page-->` после ответа, перед личными заметками. |

При привязке страницы номер записи Anki проставляет Rudonium. Для связи через YAML используется `anki-page-ID`. Страницу-карточку со старым ключом `rudonium-id` синхронизация пропустит и укажет причину. Если это единственная связь страницы, переименуйте ключ, сохранив цифры, дату и комментарий. Если присутствуют оба ключа, сначала сверьте номер записи в Anki и оставьте подтверждённый номер только в `anki-page-ID`. Собственное свойство YAML `ID` можно использовать для номера объекта в вашей базе.

#### Дополнительные поля Anki

Чтобы добавить поле в редакторе, откройте палитру команд и выполните **Добавить поле страницы Anki…**. Выберите поле из сохранённого списка полей типа записи, введите значение и подтвердите. Например, выберите `Example` и введите `Wir essen im Wirtshaus.` Команда вставит поле в заметку и при необходимости создаст раздел. Для нескольких значений нажимайте **Вставить и добавить ещё**, а для последнего — **Вставить поле**. Поле можно заполнить при закрытом Anki. Изменение отправится при обычной синхронизации.

Чтобы указать дополнительные поля вручную, поставьте после основного ответа отдельную строку `<!--anki-fields-->`. Каждое поле начинайте с новой строки, указывая его точное имя в Anki и двоеточие. Если имя неизвестно, Rudonium подскажет допустимые имена полей этого типа записи. Первыми будут похожие по написанию. Исправьте имя и повторите синхронизацию. Значение может продолжаться на следующих строках. В примере у типа записи есть поля `Example` и `Translation`.

```markdown
---
tags: [anki-page, словарь]
anki-page-ID: '1700000000001'
---
# Как переводится немецкое слово Wirtshaus?

Трактир.

<!--anki-fields-->
Example: Wir essen im Wirtshaus.
Das Wirtshaus liegt am Marktplatz.
Translation: Мы едим в трактире.
Трактир расположен на рыночной площади.

<!--rudonium-answer-end-->
Мой источник: [[Путевые заметки]]
```

В Anki попадут четыре отдельных значения — вопрос, ответ, пример и перевод. Используйте имена полей своего типа записи. Каждое дополнительное поле можно указать один раз. Вопрос и ответ уже взяты из заголовка и текста. Поля, назначенные для ссылки на файл и контекста, заполняет Rudonium. В обычном ответе выше метки можно свободно использовать двоеточия. При выборе **После ответа** служебная строка ID записывается после последнего дополнительного поля. [Как синхронизируются именованные поля](#как-синхронизируются-именованные-поля)

Если в словарном типе записи есть поля `FrontLang` и `BackLang`, при одностороннем экспорте можно задать `FrontLang: ru_RU` и `BackLang: de_DE`. Обратная запись языковых полей из Anki в Markdown защищена.

Для обычного вопроса и ответа раздел полей можно пропустить. Чтобы сохранить личные заметки на той же странице, начните их с отдельной строки `<!--rudonium-answer-end-->`. Эта строка и весь текст ниже остаются в Obsidian.

Если в странице есть граница личных заметок, в режиме **Удалить блок** после удаления записи из Anki сохраняются Markdown-страница и её прежний ID. Так личные записи остаются защищёнными и при следующем экспорте. Эта особенность указана в предпросмотре удаления.

В варианте **После ответа** скрытая строка ID следует за последним полем. Можно поместить `#anki-page` отдельной строкой после ID, перед личными заметками. Пример строки с датой — `<!--ID: 1700000000001 | 2026-11-20 @page-->`. Служебная пометка `@page` отличает ссылку страницы от обычного ID другой карточки. Команды приостановки и удаления для такой страницы ставятся сразу под первым заголовком первого уровня.

#### Перенос ID существующих страниц

Для открытой страницы выберите нужное расположение в настройках и выполните команду **Перенести ID этой страницы**. Правку можно отменить в редакторе.

Для переноса по всему хранилищу откройте **Маркеры ID Anki → Перенести ID страниц…**, выберите исходное и целевое расположения и нажмите **Предпросмотр**. Чтобы перевести старые страницы на новый формат по умолчанию, выберите **Под заголовком → В свойствах (YAML)**. Проверка охватывает всё хранилище, включая файлы за пределами текущего профиля папок. Посмотрите, какие страницы подходят и по каким причинам пропущены остальные. Отметьте нужные страницы и нажмите **Создать ZIP и перенести (N)**.

До первой правки Rudonium создаёт и проверяет ZIP всего хранилища Obsidian, включая настройки и вложения. При ошибке резервного копирования файлы сохраняют прежнее содержимое. Перенос меняет Markdown локально и сохраняет прежний номер записи Anki и распознанную дату. Если в строке ID есть авторское примечание, вынесите его в отдельное свойство или строку и повторите предпросмотр. Сохраните путь к ZIP из результата операции. Копию можно открыть через **Резервные копии → Восстановить в новую папку**. [Перенос файлов других плагинов](migrate-card-files.md)

Yanki сохраняет номер записи Anki в свойствах страницы. Deck To Anki использует YAML для режимов Card и Title. У Obsidian_to_Anki скрытый ID располагается после полей карточки. В третьем варианте Rudonium использовано такое расположение и добавлена собственная пометка владельца `@page`. [Yanki](https://github.com/kitschpatrol/yanki-obsidian/blob/main/README.md#can-i-delete-the-noteid) · [Deck To Anki](https://github.com/PandaNocturne/obsidian-deck-to-anki/blob/master/README.md) · [Obsidian_to_Anki](https://github.com/ObsidianToAnki/Obsidian_to_Anki/wiki/Updating-existing-notes)

### Правки со стороны Anki

Карточка с ID, созданная по правилу мастера, может принять текстовые правки из Anki. В последнем поле многострочной карточки сохраняются абзацы. Запустите двустороннюю синхронизацию заметки, раскройте изменённое поле и нажмите **Как изменится это поле в Markdown**. Плагин покажет исходный блок и результат выбора значения из Anki. Если поле изменили с обеих сторон, по умолчанию используется версия с более поздним подтверждённым временем изменения. В предпросмотре стрелки показывают доступные направления переноса. Сравниваются время файла Markdown и время записи Anki с точностью до секунды. Время относится к записи и файлу в целом. При первой двусторонней сверке плагин сначала учитывает подтверждённые значения одностороннего экспорта. Если по ним источник изменения неизвестен, время файла сравнивается со временем каждой связанной записи Anki, в том числе для нескольких ID в одном файле. Если обе программы изменили несколько сопоставленных текстовых полей одной записи, для этих расхождений используется время файла и записи. После первой сверки плагин также проверяет, могла ли измениться соседняя карточка или другой текст файла. При одинаковой секунде, отсутствии времени или неоднозначных изменениях после сверки выберите направление вручную. Если значение из Anki содержит разделитель полей и его нельзя вставить в Markdown, для проверенного значения доступны отправка из Obsidian в Anki и пропуск.

Для обычного поля поддерживается простое полужирное выделение. Например, Markdown `**Мариинскую колонну**` соответствует `<b>Мариинскую колонну</b>` или `<strong>Мариинскую колонну</strong>` в Anki. Если у тега есть атрибуты, границы выделений пересекаются или сопоставление полей неоднозначно, проверьте запись вручную.

Для однострочных ручных выражений поддерживаются якоря `^` и `$`, группы `(.+?)` или `(.+)` и однозначные текстовые разделители. Например, правило `^Q=(.+?) -> A=(.+)$` позволяет менять ответ с сохранением подписей. Если новое значение содержит границу поля, в карточке сложный HTML или выражение нельзя однозначно прочитать в обратном направлении, проверьте разметку вручную. Группы должны соответствовать порядку полей в Anki. Для дополнительных полей сохраняется заданное направление синхронизации. Служебные и защищённые поля обрабатываются отдельно.

Перед записью Rudonium проверяет предлагаемый текст тем же разборщиком, который используется при экспорте. Если меняется принадлежность карточки или её колода, потребуется ручная проверка. Сохраняются ID, остальные поля и переводы строк исходного файла. Для встроенных форматов продолжают действовать их правила, в том числе поля `ob-deck-front` и `ob-deck-back` на перенесённых страницах Deck To Anki.


### Своё регулярное выражение

Располагайте группы захвата в порядке полей Anki. Например, выражение ниже помещает текст после «Вопрос:» в первое поле, а текст после «Ответ:» во второе. Вводите выражение без косых черт по краям.

```regex
^Вопрос: ([^\r\n]+)\r?\nОтвет: ([^\r\n]+)
```

```markdown
Вопрос: Столица Австрии?
Ответ: Вена
```

В быстром старте вставьте пример в поле **Пример Markdown** и нажмите **Проверить пример**, чтобы увидеть захваченные значения. Перед экспортом откройте предпросмотр сохранённой заметки. От формата зависит, какой текст плагин распознает как карточку. Если у записи уже есть ID Anki, сохраните его рядом с соответствующим текстом.

#### Очистка ответа связанной карточки

На уже связанной карточке очистите поле ответа в Anki и запустите двустороннюю синхронизацию. После удаления слова `Bahnhof` строка выглядит так. Между разделителями останется пустое место для ответа. Вопрос, параметр языка и ID сохранятся.

```markdown
- Как по-немецки «вокзал»? ::  :: B=de_DE
```

Если вы также изменили ответ в Markdown, откройте предпросмотр и выберите, какую версию сохранить. При одностороннем экспорте источником остаётся Markdown. Дополнительные поля Anki, которые ваше выражение не захватывает, не добавляются под ID.

В одностороннем режиме новое значение обычного текстового поля из Markdown обновляет уже связанную запись, даже если текст успели изменить и в Anki. Это правило действует после первой подтверждённой сверки поля. Если менялось только значение в Anki, оно сохраняется. При первом расхождении, одновременной очистке и правке, конкурирующих правках форматированного текста, формул или карточек с пропусками или изменении состава учебных карточек нажмите **Предпросмотр экспорта файла** в уведомлении и сравните значения.

## Как синхронизируются именованные поля

Эти правила действуют для дополнительных редактируемых полей у связанных карточек в блоках `START` / `END` и на страницах-карточках. В примере у типа записи Anki есть поле `Импортированный`.

| Что изменилось | Односторонний экспорт | Двусторонняя синхронизация (разрешены оба направления) |
| --- | --- | --- |
| Вы удалили строку `Импортированный: Да` целиком после её синхронизации. | В той же записи Anki очистится поле `Импортированный`. Если его значение изменили и в Anki, экспорт предложит проверить расхождение. | Если значение в Anki осталось прежним, поле очистится. Если его успели изменить в Anki, можно выбрать, какую правку сохранить. |
| Вы заполнили поле в Anki. В этой карточке такого поля в Markdown ещё не было. | Значение сохранится в Anki. | Строка `Импортированный: …` появится внутри блока или в разделе полей страницы. |
| Вы очистили значение в Anki, а в Markdown осталась синхронизированная строка с прежним текстом. | Односторонний экспорт читает значения из Markdown. | Из строки в Markdown удалится прежнее значение, имя поля останется. |
| В Markdown поля нет, в Anki оно пустое. | Поле останется пустым. | Поле останется пустым с обеих сторон. |

Удаление строки распознаётся, когда в том же профиле уже была подтверждена синхронизация этого поля для той же записи. Для блоков и страниц этот учёт ведётся с версии 0.9.6. Если удалить последнее поле на странице, пустой раздел `<!--anki-fields-->` тоже можно убрать. При первом экспорте поля, которых уже нет в исходном тексте, сохраняют свои значения в Anki. Чтобы очистить такое поле вручную, добавьте строку `Импортированный:` и подтвердите изменение в предпросмотре экспорта. Подтверждение может понадобиться и при очистке поля, от которого зависит создание учебных карточек. Направление передачи отдельного поля можно выбрать в **Двусторонняя синхронизация → Дополнительные поля**.

## Ссылка на файл и контекст заголовка

Для страницы-карточки можно включить любую из этих опций или обе сразу. В **Правилах типов записей** выберите **Поле ссылки на файл** и **Поле контекста**. Для этих значений назначьте разные поля своего типа записи Anki.

| Опция | Что появится в поле Anki |
| --- | --- |
| **Добавлять ссылку на заметку** | Ссылка **Obsidian**, которая открывает источник. У связанной страницы в ссылку входит ID записи Anki. |
| **Добавлять контекст** | Путь от корня хранилища и заголовок вопроса, например `Словарь/Еда.md > Как переводится немецкое слово Wirtshaus?`. Служебный тег страницы пропускается. |

После перемещения файла или изменения вопроса выполните синхронизацию, чтобы обновить эти сведения в прежней записи Anki. Если нужно только одно значение, включите соответствующую опцию.

После переименования или удаления полей в Anki откройте **Правила типов записей** и нажмите **Обновить**. Rudonium перечислит исчезнувшие поля для ссылки на файл и контекста, а для каждого такого назначения выберет **Без поля**. Чтобы снова записывать эти сведения, откройте правило указанного типа и выберите новое поле.

## Проверить правило на своей заметке

Откройте заметку с обычными для вас карточками. В разделе **Правила типов записей** нажмите **Изменить**, при желании назовите правило, измените выражение и нажмите **Проверить на текущей заметке**. Раскройте строку, чтобы увидеть значения полей и ID. Например, свойство Dataview `Status:: In Progress` может подойти под выражение RemNote. По номерам строк удобно проверить такие совпадения до сохранения.

У табличной карточки ID ставится отдельной строкой под таблицей. Допускается одна пустая строка. Если для страницы-карточки выбрано **Под заголовком**, ID располагается сразу под первым заголовком первого уровня. Свойства YAML и отдельные комментарии над заголовком остаются в Markdown. Название правила меняет подпись в Rudonium и сохраняет тип записи в Anki.
