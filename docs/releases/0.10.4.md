# Rudonium Anki Toolkit 0.10.4 · Review candidate / Кандидат для проверки

## English

This branch addresses the Community Directory findings from 0.10.3. The settings UI uses Obsidian heading controls, preview fields pass through the Obsidian HTML sanitizer and a local allowlist, and the plugin stylesheet defines layouts, expanded states and archived-card formatting. The manifest keeps the same plugin ID, desktop requirement and minimum Obsidian version. The published 0.10.3 instructions remain applicable to that release.

To build from a clean checkout with Node.js 22.18 or later, run `npm ci`, `npm run build` and `npm test`. For the verified distribution run `npm run release:prepare` or double-click `Prepare-GitFlic.cmd` on Windows. The preparation script compares the candidate assets against two independent clean builds before writing the installation ZIP. `PROVENANCE.json` in the starting checkout describes the previous 0.10.3 build; the prepared output contains a freshly generated record for this build. An installation ZIP contains the runtime and notices. The prepared repository and install ZIP must be kept together for distribution.

Publish the review branch to both remotes from the same commit. In the directory owner’s dashboard select **Review branch**, enter `fix/obsidian-review-0.10.4` or its SHA, and run the preview scan. Confirm zero blocking errors and test the built files in desktop Obsidian with a test Anki profile. Then tag that reviewed commit. Attach the ZIP and its checksum to GitFlic, and upload the three individual files `main.js`, `manifest.json` and `styles.css` to the matching GitHub release. [Directory review](https://docs.obsidian.md/community-directory/manage-entry)

## Русский

Ветка исправляет замечания каталога к версии 0.10.3. Заголовки настроек создаются средствами Obsidian. При предпросмотре HTML проходит очистку в Obsidian и дополнительный отбор разрешённых элементов. Размеры окон, состояния кнопок и оформление удалённых карточек определены в таблице стилей. Идентификатор плагина, требование настольной версии и минимальная версия Obsidian сохраняются.

В чистом клоне выполните `npm ci`, `npm run build` и `npm test`. Для подготовки проверенного комплекта в Windows запустите `Prepare-GitFlic.cmd`. Сборщик сверит три установочных файла с результатами двух чистых сборок и покажет пути к готовым файлам. Исходный `PROVENANCE.json` описывает сборку 0.10.3. Для распространения 0.10.4 используйте вновь сформированные сведения из результата подготовки.

Отправьте ветку проверки на оба сервера. В панели владельца записи каталога выберите **Review branch → fix/obsidian-review-0.10.4 → Run preview scan**. Перед созданием тега проверьте нулевое число блокирующих ошибок и работу плагина в настольном Obsidian с тестовым профилем Anki. Тег должен указывать на проверенный коммит. На GitFlic прикрепите установочный ZIP и контрольную сумму. На GitHub прикрепите отдельными файлами `main.js`, `manifest.json` и `styles.css`.

## Local ESLint

The root flat config loads the official recommended Obsidian preset. The Windows build and the independent lint job are defined in `.github/workflows/review-candidate.yml`. A push to the review branch runs both jobs when Actions is available. The lint job installs its tooling separately so that lint dependencies do not change the production lockfile. Its JSON output and the Windows candidate assets are workflow artifacts. The directory owner runs the portal preview separately for the same SHA. [Official lint configuration](https://github.com/obsidianmd/eslint-plugin/blob/master/docs/configuration.md)
