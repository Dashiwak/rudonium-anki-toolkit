# Rudonium Anki Toolkit 0.10.11

## Русский

- При переключении между односторонним экспортом и двусторонней сверкой учитывается последнее подтверждённое изменение обычных полей вопроса и ответа. Это помогает правильно перенести последующую правку, в том числе возврат текста к прежнему значению.
- Кнопка «Повторить» в прежнем отчёте одностороннего экспорта проверяет режим и профиль Anki перед записью.
- При ручной двусторонней сверке плагин перечитывает сохранённый текст активной или явно выбранной заметки. Он замечает в ней внешнюю правку или добавление повторного ID, даже если время и размер файла сохранились и Obsidian пропустил событие изменения.
- Если AnkiConnect отклоняет запрос сведений сразу о нескольких записях из-за одного исчезнувшего ID, экспорт проверяет, какие ID ещё существуют, и обрабатывает остальные связанные записи.
- Если формулу MathJax или текст с пропуском (cloze) одновременно исправили в Obsidian и в Anki, односторонний экспорт сохраняет обе версии до выбора в предпросмотре.
- В карточках START/END строка ответа вроде `ENDURANCE` или `ENDI` сохраняется целиком. Плагин находит завершающий маркер блока и привязанный к нему ID. В строке ответа `Back: номер ID: 123` число считается частью ответа. В карточке STARTI упоминание номера перед явной меткой ID сохраняется. При нескольких неоднозначных открытых ID экспорт останавливается до записи.
- Если ключ ID страницы записан с ошибкой в регистре, его числовое значение учитывается при поиске дубликатов. Совпадение с ID другой страницы или блока требует проверки пользователем. Упоминание `#anki-page` внутри Markdown-ссылки больше не выбирает страницу целиком для экспорта.

Установочные файлы `main.js`, `manifest.json` и `styles.css` находятся в `Rudonium-Builds/0.10.11/install/`. Для подготовки файлов выпуска используется `Prepare-Release.cmd`. [Порядок сборки](../../PUBLISHING.md)

## English

- Switching between one-way export and bidirectional sync uses the most recent confirmed change to ordinary question and answer fields. Subsequent edits, including a deliberate return to an earlier value, are compared with the right baseline.
- Retry from a previous one-way export report checks the current sync mode and Anki profile before writing.
- A manual bidirectional sync rereads the active or explicitly selected note. It can detect an external edit or newly duplicated ID in that note even if the timestamp and size stayed the same and Obsidian missed the change event.
- When AnkiConnect rejects a batch because one note ID has disappeared, export verifies which requested IDs still exist and continues with the remaining linked notes.
- If an Anki field containing a MathJax formula or a cloze deletion was edited on both sides, one-way export keeps both versions until you choose which to use in the export preview.
- A START/END card can contain an answer line such as `ENDURANCE` or `ENDI`. The parser keeps the full answer and finds the closing marker and its existing note ID. A number in a field such as `Back: case ID: 123` remains part of the answer. An inline STARTI card can mention an ID in text before its explicit ID marker. If several plain ID markers are ambiguous, export stops before writing.
- An incorrectly capitalized page ID property still reserves its numeric ID during duplicate detection. A match with another page or block requires manual review. Mentioning `#anki-page` inside a Markdown link no longer selects the entire page for export.

The three installation files are in `Rudonium-Builds/0.10.11/install/`. Use `Prepare-Release.cmd` to prepare the release files. [Build instructions](../../PUBLISHING.md)
